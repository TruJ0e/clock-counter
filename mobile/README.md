# TruTimeClock Mobile — developer beta

The desktop timer's existing web engine powers both mobile wrappers. The mobile app bundles its HTML, CSS, clock engine and sound assets, so it does not depend on the desktop PC, a tunnel, or a paid API.

## Android

- Source: mobile/android (native Kotlin + offline WebViewAssetLoader).
- Install/debug-build: download the GitHub Actions TruTimeClock-Android-floating-debug artifact, extract it and install the APK on an Android device with sideloading enabled.
- Launch the app and use its full-screen retro timer. Tap FLOAT and grant Android's Display over other apps permission when prompted. The native overlay appears, follows the selected timer, and remains visible while you switch apps.
- Drag the arrows to move it, tap the square to collapse or expand, or tap the close symbol or STOP FLOAT to dismiss it.
- A foreground-service notification remains visible while floating mode is active. Scheduled and running timers derive remaining time from absolute timestamps, so moving away from the app does not stop the floating display.
- On Android 13+, allow notifications for completion alerts. Some devices aggressively restrict overlays, notifications or background activity; test on your actual device.
- Native overlay uses SYSTEM_ALERT_WINDOW, a foreground-service specialUse type, and no remote desktop or server capability. It only starts after an explicit tap while the main activity is visible.
- Current beta follows the selected countdown or scheduled timer. More complex sequences, smartwatch integrations, and full cross-device timer sync are future work.
- Debug APKs are for testing, not distribution as a production app. Their test signing certificate is generated by CI and won't provide guaranteed upgrades between runs. Production distribution needs an owner-controlled release signing key and Google Play review.

## iPhone / iPad

- Source: mobile/ios (native SwiftUI + WKWebView and ActivityKit / WidgetKit).
- Reuses the same bundled offline timer interface and offers a SHOW LIVE button to place an active countdown on the Lock Screen and, on supported iPhones, the Dynamic Island.
- Live Activities require iOS 17+ and compatible hardware; not all iPhones have a Dynamic Island. They aren't arbitrary floating windows and cannot sit above every app like FaceTime Picture in Picture.
- The countdown's end timestamp is sent to ActivityKit so the system renders the remaining time without frequent background JavaScript updates.
- With permission, a native local notification is scheduled for the end of a running countdown. It is removed when the Live Activity is stopped. Any timer changes made while the app is suspended may not synchronize until reopening.
- The CI workflow builds an unsigned Simulator app and its widget extension. It cannot create a directly installable production iPhone IPA or App Store submission without the owner's Apple Developer signing credentials and app provisioning.
- To install on a physical iPhone, configure bundle IDs, signing team, capabilities and provisioning in Xcode, then build from mobile/ios/project.yml using XcodeGen.
- Apple's AVKit Picture-in-Picture is designed for video/calls. This project deliberately does not disguise a timer as video to bypass system restrictions or risk App Store rejection.

## Build and test

1. From the repository root, run npm run build:mobile. This regenerates shared offline assets from the full app into mobile/android/app/src/main/assets and mobile/ios/Web.
2. npm run test:mobile tests the browser bridge, offline asset loading and script security.
3. Android: install JDK 17, Android SDK 35 and Gradle 8.13; run gradle assembleDebug in mobile/android.
4. iOS: on a Mac, install Xcode and XcodeGen, run xcodegen generate in mobile/ios, then build the TruTimeClockMobile scheme for an iOS Simulator.
5. The public GitHub Actions workflow build-mobile.yml builds both targets without signing secrets and uploads clearly marked development artifacts.

There is no background connection between either mobile app and your computer. All data remains local unless you explicitly export a timer setup. The Android permission to draw over apps is sensitive, so it should be requested only when the user chooses Float. Do not publish this beta to the stores until device testing, accessibility review, signing and privacy review are complete.
